# 本地操作界面

这是供队员演示和运行当前正式M2基线、查看逐目标状态的本机网页界面，不需要安装前端框架，也不会把比赛文件上传到互联网。

## 启动

在项目根目录执行：

```bash
.venv/bin/python web_app.py
```

然后在同一台电脑的浏览器打开 `http://127.0.0.1:8765`。按 `Ctrl+C` 关闭界面。

## 使用

1. 上传卫星TLE文件，格式为每颗卫星三行：名称、TLE第1行、TLE第2行。
2. 上传站点文本，每行采用 `编号：经度, 纬度, 海拔(m)` 格式。
3. 选择全部10,000个目标，或选择前1,000个目标作快速试运行。
4. 点击“检查文件”。系统校验结构和SHA-256；只有与当前正式D窗口完全一致的输入才允许继续。
5. 选择调度策略并点击“生成调度并验收”。完成后页面显示覆盖、得分、观测数、利用率和独立裁判结论，可下载调度CSV及裁判明细CSV。

## 卫星状态分析

打开“卫星状态分析”页签，点击“生成状态分析”。系统会将TLE、A层目标状态表和D窗口按规范化目标ID关联，展示轨道类型分布、TLE历元、传播状态、D窗口数量、满足120秒的机会、可用站点和最长窗口。页面按合格窗口数量、可观测机会时长、站点数排序，列出机会最少的目标，并支持搜索、优先级和状态筛选、点击查看详情、导出完整目标CSV。

可选导入M2排程CSV。项目标准CSV的 `start_s`、`end_s`、`duration_s` 会转换为UTC计划开始/结束时刻，并显示目标的逐次任务、站点和时长；每次时长是否落在120–240秒范围会单独标出。没有时间列的排程仍可统计任务次数，但无法显示逐次时刻。这里展示的是计划时段，不是望远镜实际执行日志，也不等于Referee验收；须单独运行Referee才能确认计划合法。

## 当前支持范围

当前运行入口使用正式规划区间 **2026-08-01 00:00至2026-08-07 00:00 UTC**、本机已配置的优先级文件和经过哈希锁定的D受光窗口。界面不会因为上传了不同TLE或站点文件而沿用旧窗口；输入SHA-256不一致时会停止并要求先为新输入重算、验证M1 A/B/C/D缓存。这样可以避免生成貌似成功、实际引用过期窗口的结果。

页面不把TLE历元差称为卫星“年龄”；TLE历元仅表示轨道数据对应的时间。观测时刻和持续时间来自排程CSV中的任务起止时刻，显示为UTC计划值。轨道类型是按TLE均根数推导的展示性启发分类。传播异常会标为“需核查”，不能单凭传播错误宣称卫星已经脱轨。D层站点机会时长是跨站窗口时长相加，同一时刻可能包含多个站点机会，不是唯一可用时间。

“创新方向”卡片区明确区分当前界面已有证据和仍需数据验证的内容：排程可展示跨站重复任务；要声称天气备份提高成功率，需要输入站点天气情景并计算对照；多周期鲁棒性需要其他规划周期的数据；效率卡片显示单次运行耗时，跨周期/多种子比较需单独实验。

界面是本地演示入口，不是通用窗口生成器。它只监听 `127.0.0.1`，作业结果写到被Git忽略的 `output/ui_runs/`。需要正式使用完整10,000目标时，请确认本机D缓存、状态表、优先级文件和DE421星历均已按项目清单准备好。
